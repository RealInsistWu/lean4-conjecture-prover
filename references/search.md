# Adaptive search and audit

Load only for substantial, stalled, multi-agent, or resumed work.

## Allocate by evidence

Start with independent mechanisms appropriate to the domain. Examples: minimal counterexample or well-founded induction; decomposition and gluing; symmetry, invariants and extremal exchange; algebraic or spectral representations; duality and optimization; topology, geometry, analytic estimates, probabilistic constructions; compactness or descent. Do not enumerate irrelevant families.

Ask why the statement could hold, what obstruction would make it false, what survives a simplified model, and which missing lemma would supply an actual new mechanism. Use exact or certified computations for finite claims. Exploratory numerics and finite tests of an infinite claim are not proofs.

The coordinator owns the contract and shared record. Give workers a compact packet: contract, source mode, assigned mechanism or gap, relevant checked lemmas, and available budget. Request only concrete mathematical results: statement, derivation or witness, dependencies, and precise obstruction. Early workers should not see the favored approach. Do not send all prior transcripts to every worker.

Run independent attacks on high-risk claims. Scale up only when independent subproblems or unexplored mechanisms justify it; shrink when routes converge. Keep incompatible routes alive while each has real prospects. Do not repeat the same missing theorem under renamed variables. Share validated insights after independent exploration; preserve provenance and unresolved assumptions. Never claim that agents ran if they did not.

## Compact records

Use `assets/checkpoint.md` as a template if work spans rounds or sessions. The ledger is a research aid, not a proof. Keep proof text and evidence in separate task-local files when useful; refer to them by path and lemma ID. The coordinator merges results; workers should not concurrently overwrite shared files.

Route statuses: active, promising, blocked, refuted, closed. Record a new mechanism before reopening a blocked route. Distinguish failure of an approach from refutation of the conjecture.

For serious candidates, maintain a sparse dependency DAG: target -> required lemmas -> proved facts or checked references. Give every node a precise statement and evidence location. Detect cycles and equivalent-strength missing leaves. A missing edge or hypothesis is a gap, not an administrative issue.

Save a checkpoint after material progress and before handoff or context reset. Resume from the frozen contract and latest checkpoint; reopen referenced evidence only as needed. Never silently change source mode or reset prior failures. Stop at the actual resource boundary and return the strongest justified result, not an invented verdict.

## Skeptical audit

Give an independent reviewer the contract, candidate, and necessary sources, but not the expected verdict. Request the first substantive gap, its location, and a counterexample if available. Check quantifier order, witness dependence, exact domain and equality, multiplicity/orientation, empty or singular cases, induction decrease, limit and uniformity arguments, theorem hypotheses, gluing and reconstruction, and circular dependencies. Select checks relevant to the problem. A reviewer vote does not establish correctness.

Repair or abandon defective arguments. Re-audit affected dependencies after meaningful changes. If reviewers are unavailable, do an explicitly separate skeptical pass and say it was not independent. Prefer a short genuine proof over a long search report.
